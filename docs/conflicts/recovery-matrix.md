# Recovery comparison: detailed evidence

| Situation | Caused by | Verdict | Lifecycle Center-only path | Git path | Evidence |
|---|---|---|---|---|---|
| [A work item's PR conflicts with its stage branch](work-item-conflict.md) | Two work items changed the same lines; one reached the stage first | **Git recommended** | Never the work item → Back Sync its dev org → redo the change → new work item. The developer's change is overwritten and must be redone by hand. | Merge the stage branch into the work item branch, resolve, push. Keeps the developer's work. | **Observed** ([Exp 01](../lab/01-same-lines-conflict.md) Git, [Exp 07](../lab/07-b8-never-and-redo.md) Lifecycle Center) |
| Bundle of overlapping work items blocked going into the first stage | Promoting conflicting work items together | **Git recommended** | Promote them one at a time, then as in the row above | As above, for the second work item | **Observed** ([Exp 01](../lab/01-same-lines-conflict.md), [Exp 07](../lab/07-b8-never-and-redo.md)) |
| [Stuck stage after a combine that threw away a manual resolution](stuck-after-combine.md) | Combine rebuilt the work item from `main`, ignoring the hand-resolved commit | **Git recommended** | Accept the target version: a work item that copies Production's version into Staging. Ships the **untested** combine result, and you need a second work item to restore Staging's version. | Reconcile stage branches: merge `main` into `staging`, keep Staging's lines | **Observed** ([Exp 02](../lab/02-stage-promotion-after-combine.md) Accept the target version, [Exp 06](../lab/06-a3b-git-merge-recovery.md) Reconcile stage branches) |
| [Stuck stage after a custom promotion, stuck work item already in Staging](stuck-after-combine.md#fix-c-custom-promote-the-stuck-work-item-lifecycle-center-only) | Custom-promoting the older of two same-line work items | **Git recommended** | Custom-promote the source version: custom-promote the stuck work item (Never isn't offered once a work item is Promoted). Ships Staging's version, but leaves split history, so the next edit to those lines blocks again. | Reconcile stage branches: merge `main` into `staging`, which repairs this history divergence | **Observed** ([Exp 08](../lab/08-c3-stuck-stage-promoted-wi.md)) |
| Production silently rolled back after out-of-order custom promotions | Custom-promoting the newer stuck work item, then the older one alone | **GitHub to diagnose** | Two throwaway work items + Combine restores the exact value (**Observed**, [Exp 11](../lab/11-c3f-recover-silent-rollback.md)). Nothing in the UI shows the problem. | Reconcile stage branches + a promotion with "All changes in the … stage branch" | **Observed** ([Exp 10](../lab/10-c3e-silent-regression.md), 11) |
| Same, with **two** stuck work items on the same line | As above | **Git recommended** | Custom-promote the source version with **Combine** (Continue fails cleanly with `MERGE_CONFLICT`). Same trap left behind. | Reconcile stage branches | **Observed** ([Exp 09](../lab/09-c3d-fix-c-two-stuck-wis.md)) |
| [Stuck stage from the latent trap after a "clean" combine](stuck-after-combine.md#prevention) | Combine left identical content but separate histories; a later work item touched those lines | **Git recommended** | Accept the target version, which means first undoing your new change to match Production, then shipping it again | Reconcile stage branches ([Exp 06](../lab/06-a3b-git-merge-recovery.md)) | **Observed** ([Exp 06](../lab/06-a3b-git-merge-recovery.md)) |
| [Two work items combine into a failing test](test-failures.md) | Semantic conflict: each passes alone, Git merges cleanly | No Git needed | Back Sync, fix, new work item, promote with tests | – | **Observed** ([Exp 13](../lab/13-e1-combined-test-failure.md)) |
| [A combined work item fails its tests, held-back work in Staging that **can be reverted**](test-failures.md#when-the-broken-version-only-exists-in-a-combined-work-item) | Combine (or Prepare) dropped a hand-resolved line | **Git recommended** | [Revert all the held-back work](test-failures.md#the-revert-route) with a new work item, Promote Stage with tests, redo the pending work ([Exp 16](../lab/16-e6b-revert-pending-then-promote-stage.md)): two extra work items, and the reverted work item shows Closed. If the pending work **added** a component, revert by deleting it, and promote with "All changes in the Production stage branch" (the default fails on the deletion; [Exp 17](../lab/17-e6c-revert-added-component.md)). **Not acceptable:** ship the broken combine, then fix forward ([Exp 14](../lab/14-e6-fix-broken-combine.md)). Combining a fix-up work item in fails. | [Commit Staging's files onto the combined branch](test-failures.md#the-git-fix) after Combine, then promote with tests ([Exp 15](../lab/15-e6a-git-fix-for-broken-combine.md)) | **Observed** ([Exp 14](../lab/14-e6-fix-broken-combine.md)–17) |
| [A combined work item fails its tests, held-back work in Staging that **can't be reverted**](test-failures.md#when-the-broken-version-only-exists-in-a-combined-work-item) | As above, but some held-back work must stay in Staging (still in testing, too big to redo) | **Only tested recovery uses Git** | None acceptable: Promote Stage would ship the held-back work, and a custom promotion (Combine) rebuilds the broken version. Shipping it broken and fixing forward ([Exp 14](../lab/14-e6-fix-broken-combine.md)) doesn't count. | [The Git fix](test-failures.md#the-git-fix) ([Exp 15](../lab/15-e6a-git-fix-for-broken-combine.md)) | **Observed** ([Exp 14](../lab/14-e6-fix-broken-combine.md), 15); reasoning from [Exp 16](../lab/16-e6b-revert-pending-then-promote-stage.md)–17 |
| Promote Stage fails: *"destructiveChanges.xml: No ApexClass named: … found"* | A work item deleted a component that never reached Production (e.g. reverting a new component) | No Git needed | Retry Promote Stage with "All changes in the Production stage branch" and tests covering all Apex in the branch. That option never deploys deletions ([Exp 18](../lab/18-e6d-all-changes-and-deletions.md)), so ship any real deletion separately with the default option. | – | **Observed** ([Exp 17](../lab/17-e6c-revert-added-component.md), 18) |
| Content committed straight to a stage branch (not through a work item) | Git outside Lifecycle Center | **GitHub to diagnose** | Nothing redeploys or warns. The default Promote Stage merges it into `main` but deploys it only if a promoted work item touches the same file. To bring the orgs in line: a carrier work item → Staging with "All changes in the Staging stage branch" → Promote Stage with "All changes in the Production stage branch" (tests for all Apex in the branch). | Don't do it. Compare branches with the orgs to find it. | **Observed** ([Exp 19](../lab/19-d1ab-direct-commit-on-staging.md)) |
| A custom promotion fails at Next with "Promotion Failed: We couldn't complete this task" | A prepared PR isn't `CLEAN` in GitHub (even a non-required failing check) | **GitHub to diagnose** | – | Look at the prepared `WI → main` PRs' checks | **Observed** ([Exp 14](../lab/14-e6-fix-broken-combine.md)) |
| [Any Promote Stage conflict](where-conflicts-show-up.md#the-ui-doesnt-name-the-files): which files? | – | **GitHub to diagnose** | The popup names no files or work items | Open the stage PR, or `git merge-tree` locally | **Observed** ([Exp 02](../lab/02-stage-promotion-after-combine.md)) |
| Spotting the latent trap *before* it bites | A combine | **GitHub to diagnose** | Nothing in the UI | `git merge-base origin/main origin/staging` | **Observed** ([Exp 06](../lab/06-a3b-git-merge-recovery.md)) |
| A work item commits a stale version from a dev org that's behind | Dev org not refreshed after other work shipped (D6) | **GitHub to diagnose** | **Never** on the work item, **Back Sync** the dev org, then redo it | – (only the PR diff shows the revert) | **Observed** ([Exp 05](../lab/05-b3c-combine-dialog-trigger.md), Back Sync [Exp 07](../lab/07-b8-never-and-redo.md)) |
| Required check fails on the stage PR | Your own [branch protection](../guardrails/branch-protection.md) gate | **GitHub to diagnose** | Click Promote Stage again once the check passes | Fix whatever the check reports | **Observed** ([Exp 03](../lab/03-e5-branch-protection-gate.md), 04) |
| Prepared `WI → main` PRs and branches left open after the work items ship via Promote Stage | Custom promotion that was abandoned | **GitHub housekeeping** | – | Close the PRs, delete the branches | **Observed** ([Exp 04](../lab/04-g1-staging-provenance-check.md)) |
| Stage PR left open after a combine | Combine | **GitHub housekeeping** (harmless) | It rides along with the next Promote Stage | – | **Observed** ([Exp 05](../lab/05-b3c-combine-dialog-trigger.md)) |
